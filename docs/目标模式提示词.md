# 目标模式提示词 · desens-desktop

本项目进入「自主推进」阶段后，每开一个新会话都会面对同一件事：**目标是什么、能自己决定什么、
什么绝对不能做**。把这几段提示词固化下来，新会话不需要重新考古，也不必每一小步都回头确认。

用法：把 §1 作为新会话的第一条消息；§2–§5 是它的附件，可整段贴入，也可由我在需要时引用。
§6 是状态块——**换会话时必须带上**，否则新会话会把已完成的事重做一遍。

## §2 目标定义与验收标准（DoD）

DoD 必须**可核查**，不接受「差不多了」。每一块交付都要同时满足四条：

| 项 | 判定口径（不是「看起来对」） |
|---|---|
| 单测 | `mvn test` 全绿，且**用例数**逐类可见（不许只看总计行——`@TestFactory` 的总计行是容器计数不是用例数） |
| 对照实验 | 撤掉实现后测试必须变红；靠抛异常变红判无效；死循环类变异要求 surefire fork 确实崩溃 |
| 端到端 | 走**打包后的 jar + 命令行**，校验器不复用被测代码（PDF 用 PDFBox，OFD 用 ofdrw / Python） |
| 阶段文档 | 覆盖范围表、已知限制、为什么这么选型、这轮修掉的真实缺陷 |

全局 DoD：
- 核心包 ≤90MB（全量 L0+L1+L2）；
- 五种格式全部覆盖，且每种都有一份「容易漏的位置」清单；
- 文档内容零外发；
- Windows 与 macOS 安装包都能在干净机器上跑通。

## §3 质量红线（不可协商，来自已踩过的坑）

```text
1. 红灯原因必须正确。编译失败、抛异常、超时，都不算「测试发现了问题」。
2. 绿灯必须自证：撤掉实现要红。撤掉一层还红，通常是纵深防御在挡；撤掉一层仍全绿，多半是探针空转。
3. 前提断言必须真的成立。断言身份/前提时逐字段核对真实值，失败信息里打印实际值。
   前提不满足时要报错，不能静默跳过——宁可偶尔红，也不要一条永远为真的断言。
4. 测试标尺必须独立于被测实现。被测代码自己写、自己读、自己验，只能证明内部自洽。
5. fail-closed。解析不了就报错，绝不原样放行——静默跳过等于交付一份没脱干净的文档。
6. 面向用户的陈述不得超出系统实际核实的范围。「零命中」必须区分「文档干净」与「没有文本层」。
7. 报告里区分三种状态：已验证（跑过）、已实现（没验）、已知缺口（明确写出来）。
8. 门禁因真实缺证据而失败时，不要造假绕过。如实保持 fail 并记录前置条件，优先级高于让指标变绿。
```

## §4 每轮推进节拍

```text
一轮 = 一个可交付的小块，不是「下一步」。

开始前：读阶段文档 → 更新 TodoWrite（这是本项目的目标载体）→ 说清这一块做完的判定口径。
执行中：改代码 → 补测试 → 跑对照实验 → 跑端到端 → 更新阶段文档。
结束时：如实汇报「做成了什么 / 验证到什么程度 / 还差什么」，并把未验证项单独列出来。

节奏建议：能在一次会话里跑完对照实验时，就别拆到下一轮——
对照实验会变异源码，跑到一半停下来容易留下脏产物（源码与 class 不一致）。
要拆就按「变异 + 基线复核」这个完整单元拆。
```

【环境坑】
- bash 变量名只吃 [A-Za-z0-9_]，中文标点会被吞进变量名，用 ${var}
  （**全角标点前也必须写 ${var}**：`$VAR（` 会被解析成变量名 `VAR（` → unbound variable）

- rm -rf 相对路径、`..` 路径被网关拦截；heredoc 写文件被拦（用 write 工具）

- 对照实验运行期间**不能**编辑 src/**、不能并行跑 e2e 或 mvn package（都写 target/）

  （**还原时还要刷 mtime**：copy2 / mv 会把 mtime 还原到变异**之前** →
   源文件比 target/classes 更旧 → Maven 跳过资源重拷贝 → **打出来的 jar 里装的是变异体**；
   2026-10-21 实测踩到：浏览器端到端三条断言全红，根因在这儿而不在代码）
- **同一个事实只许在一处定义**（路径、文件名、条数都算）：
  2026-10-21 实测踩到 —— 每路 CE 汇总文件的路径在 `ce-plan.py`（声明
  `ce-sum-224-w0.txt`）与 `ce-resume-round.sh`（硬编码 `ce-sum-w0.txt`）
  **两处定义且已漂移** → 写入方与读取方对不上 → 合并判红。
  报错是「汇总文件没有可解析的结论行」，读起来像「CE 没跑出结论」，
  **其实是路径没对上** → 症状归位：文件缺失 ≠ 内容为空。
  修法是让 plan 成为唯一真源（写入方从 plan 读），不是让读取方「两个都试」
  ——后者又造出第二处定义。改这类双定义时，**先 grep 出全部定义点**逐个对齐
- **「核对过没出现过」的那句话，本身就成了「出现过」**：
  2026-10-21 实测踩到 —— 块 23 的阶段文档里写着「改前逐个核对过：
  `ⓙ ➂ ➃  ➄  ➅  ➆  ➇ ➈ ➉` 在整个项目里**一次都没出现过**」，
  而**那句话自己**就把 `➇ ➈  ➉` 写进了项目。
  → 「某个标识符在项目里一次都没出现过」这个说法，**本身就会让它出现**。
  → 选标识符（圈号、类名、记号）前要扫**全盘文件内容**
  （文档、脚本、`work/` 目录，含 `venv`），不能只看「文档正文里提没提过它」；
  扫完记得把**这一轮新写的文档**也算进去（它也是「出现过」）
- **负控制必须「新结构 + 旧行为」，不能连签名一起退回去**：
  2026-10-21 实测踩到 —— 把被测方法整个换成「改造前的老实现」，
  而老实现的**签名**也老（少了新加的参数）→ **测试类编译不过** →
  mvn 退出码 1，但 surefire 报告里是**上一轮全绿时的旧数**
  （编译失败时 surefire **不写新报告**）→ 读起来像「测试没咬住」。
  两个坑叠在一起：① **编译失败不算「测试发现问题」**；
  ② **旧报告会被当成本轮结果**。
  → 负控制只改**行为**、保留**新签名**（这样红只可能来自断言）；
  → 自证脚本跑之前**先删上一轮的 surefire 报告**（清账一律删文件，不能只清空）
- **冻结区间的字符偏移必须与被扫描的是同一份文件**：
  2026-10-21 实测踩到 —— 对账脚本算「冻结位置」时用的是**模块全局的 ROOT**，
  而扫描是**按参数收 root** 的（自证里传的是一份**假项目**）→
  冻结区间算在了真项目上 → 拿去套假项目 → **豁免落空** →
  冻结位置里的历史数被误报成「当前值不对」。
  症状：覆盖守卫的自证在**基线**上就报「抓到 1 处残留」，而真项目上一切正常 ——
  看着像判据坏了，真因是**算错了文件**。
  → 凡是把「区间/偏移」这类**位置相关**的东西算出来，都要问一句
  「它是相对**哪一份**文件算的」
- **CE 变异的圈号不是全局唯一的**：`ONLY='破坏[ⓐⓑⓒⓓⓔ]'` 是 `grep -qE` 匹配，
  圈号一撞就会把**别的块**的变异一起拉进来。2026-10-21 实测踩到：
  块 23 的 5 条子集跑出了 **11 条** —— 多出来的那 6 条**也全 PASS**，
  看上去「子集更彻底」，实际「子集通过」已经**证明不了「我这几条通过」**。
  → 新增圈号前**先 grep 全项目**看有没有被占用；
  改完跑一遍同一个 `ONLY`，**条数必须恰好等于新增条数**；
  圈号是有限的，**别一直用同一组**
- **CE 续跑器的 progress 文件要么删、要么写值，不能清空**：
  清空后 `[ -f "$prog" ]` 仍为真 → `cat` 成功但读到**空串** → 起点变空 →
  下游 `ce-run-all.sh` 的 `FROM="${1:-1}"` 兜底成 **1** →
  **四路全部从第 1 条开始跑**（区间重叠，**不报任何错**，
  几小时后才由合并脚本报「串段」）。
  2026-10-21 实测踩到并当场被逼停一次：杀掉正在跑的 CE →
  **变异体留在盘上**（还原代码没机会跑）→ 得手工还原 4 份源码。

- **新增章节的措辞不能撞上「文档数字对账」的形态表**：
  形态表登记了「专项端到端 N 条断言」这类句式 → 新章节若用了同样的句式，
  形态扫描会把**新章节的数**当成**别处那个键的数** → 对账报「某某键对不上」，

  ② 形态表登记它（`check-doc-numbers.py`）③ sync-docs 的声明模板引用它。

- **「合计 = 分项之和」的校验不能把类名写死成列表**：
  2026-10-21 实测踩到 —— 逐类用例数的合计校验写死成三个类做求和，
  新增第四个类之后：合计 53 与 9+12+23=44 不符 → 收尾链 rc=1。
  更隐蔽的一面：**若新增的那个类恰好让总数不变**（把 A 的条数挪给 B），
  写死列表的旧写法会**完全放过** → 判据恒真，且一声不响。
  → 求和口径要按「**实际列出的全部分项**」（`sum(per_class.values())`），
    那样以后加类自动跟上；而漏列一个类仍会被合计抓住。
  → 必填项**按轮次**要求（块 ≥ N 的日志必须有新项），不要「一律要求」
    （历史证据会作废）也不要「一律不要求」（等于没这道关）。
  → 报错文案里**不要写死数量**（「与三个分项之和不符」→ 数字会过期且指错方向）。
  → 负控制要设计成「**新结构 + 旧合计**」：旧写法放过、新写法报红 ——
    拿旧写法的副本跑一次确认它**不咬**，才算证明这条负控制有判别力。

  2026-10-21 实测踩到 —— 把某章的「三个类」改成「四个类」之后，
  它与**另一章**的声明模板撞了 → `sync-docs` 报「期望 1 处，实际 2 处」，
