## 仍然没有引入 POI

M1-a 定的原则在 xlsx 上继续成立：**OOXML 是「zip + XML」，用 JDK 自带的 zip + DOM 覆盖得更全。**

xlsx 的文本分布是有限的几个位置，全部显式列出并处理：

| 位置 | 说明 |
|---|---|
| `xl/sharedStrings.xml` 的 `<si>` | 最常见。一个字符串被多单元格引用时只存一份，改它等于改所有引用——正好符合"同值同符" |
| `<si>` 内部富文本片段 `<r><t>` | 身份证可能横跨 3 个片段，与 docx 的 run 完全同构 |
| `t="inlineStr"` 的 `<is>` | 直接写在单元格里 |
| `t="str"` 的 `<v>` | 公式的缓存显示结果 |
| 无数值单元格 | 匹配到就转成内联字符串，并**计数上报** |
| `<sheet name>` 属性 | 工作表名带姓名是常见情况 |
| `<definedName>` | 定义名称 |
| `xl/comments*.xml` | 批注 |
| `docProps/*` | 作者等元数据 |

`<si>` 内部的跨片段替换复用了与 docx 完全相同的纯函数（`SlotTextMapper`），已从
`com.litemask.docx.ParagraphTextMapper` 提升为 `com.litemask.core.SlotTextMapper`——
它是通用的文本逻辑，不属于 docx。

## 三个需要用户知情的副作用

1. **数值单元格转文本**：银行卡号常被 Excel 存成数字。脱敏后必须转成字符串，
   否则 Excel 仍显示原始数字（等于没脱）。但转成文本后**该列求和/排序会失效**。
   工具会打印明确提示，不让这个副作用默默发生。
   还原也**不会**把它变回数字类型——数字与文本在 Excel 里是两回事。
2. **工作表名被替换后，引用旧表名的公式会失效**（变成 `#REF!`）。占位符里的 `< >`
   是 Excel 合法字符，所以不需要另造映射，但仍对非法字符做了兜底替换与 31 字符截断。
3. **图表缓存值不处理**：`xl/charts/chart*.xml` 里的 `<c:pt><c:v>` 是上次计算的缓存。
   Excel 打开时会按源单元格重算，所以显示层不泄漏；但**直接解压 xlsx 仍能看到旧值**。
   已列为 M1 待办，没有假装覆盖了。

## 本阶段暴露的两类问题

### 一、测试期望写错（三处）

- 断言"工作表未被改动"时查的是 `sheet1.xml`，但 `t="s"` 的单元格那里只有下标 `<v>1</v>`，
  文本本体在 `sharedStrings.xml`——查错了文件。
- 统计占位符数量时忘了 XML 里 `<` 是实体 `&lt;`，直接对原始 XML 统计当然是 0。
- "同值同符"断言写成了"出现 1 次"，实际语义是"两处都用同一个令牌"，即出现 2 次。

### 二、真实缺陷（1 处）

**`restore` 子命令漏掉了 xlsx 分发分支**。`.xlsx` 因此落进纯文本分支，
用 UTF-8 去读 zip 二进制 → `MalformedInputException: Input length = 1`。

值得记的是它的症状：`Input length = 1` 是个完全看不出"分支没接上"的报错，
第一反应会去查 JSON 解析或编码。**实际上 `redact` 的分支是好的，只有 `restore` 漏了**——
同一个格式在两个子命令里各写一遍分发，就必然有一边会漏。
已改为两个分支并列，并补了 CLI 路径测试。

## 已知边界

- **工作表名里的中文人名（「张伟的账户」）当前无法脱敏**——规则库是纯正则的，
  没有 NER。这不是实现缺陷，是 M3 的范围。测试里也如实这么写着。
- 图表缓存值不处理（见上）。
- 不支持 `.xls`（老二进制格式）、`.et`（WPS 表格）、`.xlsm`（宏工作簿）。
- 公式本身不改，只改缓存结果；Excel 重开后会重算。
