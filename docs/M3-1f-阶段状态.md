## 二、接线：为什么改 `RedactionSession` 而不是改五个 redactor 的内部

来源必须**整篇共用一份**，这是不变量；而 `RedactionSession` 本来就是五条管线唯一的汇聚点
（docx/xlsx/pptx/pdf/ofd 各构造一个会话，把所有部件的 `redact` 调用都发进去）。
在会话上加 `List<EntitySource>` 是改动面最小、也最不容易漏的接法。

```java
public RedactionSession(String fullSourceText, List<Rule> rules, Exclusions exclusions,
                        List<EntitySource> sources)
```

**漏传一段的后果不是「少脱一点」**：那一段的 NER 命中不参与编号与去重，
同一个机构名在第 1 段发 `<机构名1>`、在漏传的第 3 段又发一个新的 `<机构名1>`——
还原映射里一个原值对应两个令牌，而用户拿到的是一份**看着正常、实则还原不回去**的文档。

### 2.1 隐藏路径也必须跑来源

`redactHidden`（工作表名 / 定义名称 / 批注 / 附件条目名 / PDF 元数据）此前调用的是
4 参重载，引擎里 `sources` 恒为 `List.of()`。
现改为两条路径都传来源，只在 `numbering` 上区分。

判据要分清**两套计数器**，否则会把一条永远为真的断言写出来：

| 计数器 | 按什么计 | 隐藏路径是否推进 | 影响什么 |
|---|---|---|---|
| `TokenAllocator` | `tokenPrefix` 全局 | **会**（令牌号可能有空洞） | 只影响显示，无功能影响 |
| `OccurrenceNumbering` | `(规则键, 原值)` | **不会** | 位置级排除「第 N 次」 |

界面依赖的是**后者**。所以判据只能建立在 occurrence 上，而 occurrence 又只能
通过排除项被观察到——测试写成「隐藏路径之后正文拿到 `<机构名1>`」是错的，
正确写法是「隐藏路径之后，正文那一处能被 `occurrence=0` 的排除项放行」。
本项目已把这条写进 `EntitySourcePropagationTest` 的注释。

### 2.2 三条新变异

| 编号 | 变异 | 撤掉后的症状 |
|---|---|---|
| ⒳ | 会话丢弃来源 | 正文里的人名机构名一个都不脱；文件正常生成、报告说成功 |
| ⒴ | 隐藏路径不跑来源 | 附件名 / 元数据里的机构名留着（正文照脱） |
| ⒵ | docx 每段落各建会话 | 所有「同值同符」单测照样全绿，坏的是**还原映射** |

⒵ 值得单说：它对**正向**性质（同一个值在两段拿到同一个令牌）是天然免疫的——
两个分配器各自从头发号，同一个值恰好拿到相同编号。只有配上
「不同段落的不同值必须拿到不同编号」这条**负向**性质才会露出来。

## 三、训练侧：两个把指标算错的问题

### 3.1 F1 分母被 `max_len` 截掉了 18%

第一版 `evaluate` 对**所有**句子一刀切 `[:256]`。MSRA test 有 12 句超长句
（最长 2427 字），它们贡献的 594 个实体——占全部 3304 个的 18%——连同金标一起消失。

两个数字同时说明这不是无关紧要的细节：

- 训练集同口径只丢 **0.3%**（最长 746 字），测试集丢 **18%**，**训练/评估分母不对称**；
- 丢掉的恰好是长段落，而推理时 `SlidingWindowNer` 会把长文按窗口扫完，
  这些实体在真实使用里是会被预测、也会被计数的。

现改为超长句**单独成批且不截断**（批内本就按 `t = max(len(x))` 补齐，不截断不会把整批撑长）。
同一把尺子下 v1 的 F1 从 0.8039 修正为 **0.7459**。

> 新增 `--eval-only <模型目录>`：不训练，直接给已导出的模型用当前口径重新打分。
> 这是把不同版本放到同一把尺子上比的唯一办法。

### 3.2 那 594 个实体里，19% 来自**一句话**

上面那 12 句里，有 1 句 2427 字独占 **629 个实体**，文体是
「邓小平同志治丧委员会名单」：**617 个人名连续罗列，实体密度 0.259/字，
是其余 3441 句的 16.5 倍**，几乎没有句法上下文。

先排除了两个想当然的解释：

- **不是长度效应**——同一句内部按 256 字分段，召回在 0.45~0.80 之间**震荡**，
  开头 [0,256) 是 0.68、结尾 [2048,2304) 是 0.50，没有随位置下降的趋势。
  而卷积感受野只有 `1+2*(1+2+4)=15` 字，模型本来就不该对「第 300 字」有意见。
- **不是 `max_len` 截断**——摘掉截断后长文内部召回依然低。

真实原因是**训练集里没有这类文体**：MSRA train 最长 746 字、实体密度 0.0157/字。

**这不是可以剔除的离群点**：卷宗当事人、律师、证人、债权人清单，
脱敏工具最典型的输入恰恰就是这种纯名单。这类文本比叙述性正文更**必须**脱干净——
漏一个名字会直接导致文书公开时侵犯当事人权益。

### 3.3 名单式语料合成 + v3 结果

新增 `tools/ner_roster_aug.py`，在**训练集自己的实体池**上合成（结构上不可能泄漏）。
3000 句 / 24206 实体，占训练句数 5.1%；另生成 200 句**不进训练**的留出集。

合成时刻意防了「合成痕迹变成捷径」：分隔符多样化（顿号/逗号/空格/换行/分号/空串）、
每句都掺非实体文本（称谓、案由、住址、日期）、括注（女）/（新华社北京…）随机出现。
修过两处合成瑕疵：机构名本身已以「事务所」结尾时不再拼后缀（否则造出
「天地法律事务所律师事务所」，模型会学到「后缀可以重复」），以及叠标点（`，，` / `。。`）。

**验证标尺是独立的那一份**：合成器自己维护 `text` 与 `tags`，靠 `_emit` 记账对齐，
而 `len(text) == len(tags)` **恰恰不能保证实体落在正确位置**。
所以用下游 `spans_from_tags`（训练与评估共用的解码口径）逐句还原并比对字面量，
400 句 0 例不一致、0 例 BIO 非法、0 例重复后缀、0 例叠标点。

### 3.4 v3 的成绩：合成集是自指标，真正判据是那篇长文

| 口径 | v2 | v3 |
|---|---|---|
| MSRA test **全集**（3304 实体） | 0.8010 | **0.8425** |
| **那一句 2427 字长文**（629 实体） | 0.5664 | **0.8158** |
| 其余 3430 句 ≤256 字（2574 实体） | 0.8498 | 0.8513 |
| 名单留出（合成，**自指标**） | — | 0.9438 |

**关键在第二行**：长文从 0.5664 提到 0.8158，而正常文本没有退化（0.8498 → 0.8513）。
合成集与留出集同模板、同实体池，0.9438 这个数**不构成泛化证据**；
而 MSRA test 那篇治丧委员会名单是真实新闻稿，模型没见过——
它的提升说明合成语料教的是**文体**而不是**记住那批名字**。

若只看合成留出集的 0.9438 就宣布达标，等于用一把只能量自己的尺子量自己。

## 四、这一轮挖出来的三个真缺陷

### 4.1 `RedactionSession.java` 里存着一个裸 NUL 字节

第 132 行的字符字面量是 `ruleKey + '\0' + original`，但源文件里存的是
**裸 0x00 字节**而不是八进制转义两个字符。

后果不是功能性 bug，而是**一整轮搜索静默失效**：`grep` / `file` / `git`
把这个 `.java` 当二进制，于是 `grep RedactionSession` **不输出任何内容也不报错**。
本项目因此有一段时间搜不动这个文件而毫无察觉。

修法：改成八进制转义 `'\0'`。**不能写 `'\u0000'`**——Java 的 Unicode 转义在
**词法分析之前**就被替换成真实字符，源文件里照样留下裸 0x00。
已在代码旁写死原因，防止下一个人「顺手清理」成空串（那会让
`("phone","138")` 与 `("phone1","38")` 撞成同一串，序号串台）。

已扫全项目 `src/**/*.java`：无其他裸控制字节。

### 4.2 v3 导出了一个**静默损坏**的模型包

名单式合成把 `\n` 当分隔符塞进句子 → `\n` 进了字符表 → `save` 写出一个空行 →
`load` **跳过空行** → 4586 个字只加载回 4585 个 → **从那行起每个字符的 id 整体错位一格**。

症状安静到极点：

| 口径 | 分数 |
|---|---|
| 训练日志（用内存里的词表） | **F1 0.8397** |
| 拿导出的 `.onnx` + `vocab.txt` 重新打分 | **F1 0.1209** |

没有异常、没有报错、推理全程正常执行、形状检查全过。
两个文件**各自都合法，合在一起才不合法**。

三道闸，逐条都用真实产物验证过会响（`work/probe_vocab_gate.py`：3 拦下 / 0 漏过）：

1. `build_vocab` 排除 `\n` / `\r`；
2. `CharVocab.save` 拒绝写出含换行符的表；`CharVocab.load` **不再静默跳过空行**
   （静默跳过就是把错位藏起来）；
3. 导出后当场对账「ONNX 嵌入行数 == 词表字数 + 1 == 训练期词表大小」，不过则中止且不落产物。

**可推广**：成对产物（模型 + 词表 / 索引 + 数据 / 表 + 描述文件）必须校验**它们之间**的一致性，
逐文件校验不够。而训练侧的指标**不能代表产物**，只有一条「只读产物」的独立验证路径能发现这类错误。
