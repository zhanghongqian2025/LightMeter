# M6 · 模型随程序分发与「普通用户不碰终端」验收记录

> 这一轮的目标：**把「装程序 → 再敲命令装模型」这件事从产品里去掉**。
> 本文件记录**实际做了什么**、**实际测到了什么**、以及**哪些没测到**。

---

## 一、这一版改了什么

### 1. 模型随安装包分发

| 之前 | 现在 |
|---|---|
| 模型包**独立分发**，用户要自己拿到 zip + .sig | 模型包**随安装包分发**（`app/models/ner-package/`），程序在首次启动时自己装 |
| `LightMeter model install …` | **界面上的「安装识别模型」**（底层复用同一套验签/换装代码） |
| `LightMeter model info` | **界面上的状态区**：状态、当前模型版本、是否支持人名/机构名 |
| 装不上只有终端里的报错 | 界面上一句**人话** + 用户能点的下一步 |

### 2. 新增/改动的代码

| 文件 | 作用 |
|---|---|
| `core/ExclusiveGate.java`（新） | 「扫描期间的独占闸门」：换模型时要先等在跑的任务跑完当前一步 |
| `core/EntitySource.java` | 新增 `isActive()`：让「模型真的参与了这次脱敏」可以被如实判断 |
| `ner/ModelManager.java`（新） | 模型生命周期总控：发现 → 验签 → 原子换装 → **真的加载一次** → 报状态 |
| `ner/ModelPackageInstaller.java` | 抽出 `extractArchive`：离线包的外层 zip 与模型包共用同一套路径穿越/zip 炸弹防护 |
| `ner/ModelPackageStore.java` | 默认搬目录动作改为**带重试**（Windows 上文件被占用时等一等再搬） |
| `ner/NerModelRegistry.java` | 暴露 `programDirectory()` / `packageOf()`（随附模型包的位置只有一处定义） |
| `server/JobStore.java` | 扫描/重扫/应用都持有独占闸门；「NER 参与了」改用 `isActive()` 判断 |
| `server/DocumentService.java` | 同上：模型没真正工作时，notes 里必须出现「人名与机构名没有被脱敏」 |
| `server/ApiHandlers.java` | 新增 `GET /api/model`、`POST /api/model/{install,import,rollback}` |
| `cli/ServeCommand.java` | 起服务时建 `ModelManager`、启动首次准备、注册安装让位 |
| `cli/InstallWatcher.java`（新） | 安装器来了 → 程序自己交还资源并退出 |
| `web/index.html` `app.js` `app.css` | 「识别模型」状态区 + 常驻提示 + 四个操作按钮 |
| `tools/package-windows.ps1` | 新增 `-ModelPackageDir`；随附模型包进包（**fail-closed** 地查）；首次启动自动装模型的验收；体积报告 |
| `tools/package-macos.sh` | 同上（**未在本机跑过**，见 §六） |
| `tools/package_offline_bundle.py`（新） | 把模型包 + 签名打成一个**单文件**离线包 |
| `tools/acceptance-model.ps1`（新） | 用**装好的程序**做验收（全程只走 HTTP，不碰命令行装模型） |
| `tools/package-identity.properties` | 版本号 1.0.0 → **1.1.4**；UpgradeCode 不变 |

### 3. 复用既有代码，不重写

验签（`ModelTrust`）、摘要与逐文件校验（`NerModelPackage`）、原子换装与历史版本（`ModelPackageStore`）
**全部复用**。`ModelManager` 只做**编排**，不重新实现任何一条判定。

### 环境

| 项 | 值 |
|---|---|

| CPU | Intel(R) Core(TM) Ultra 7 265K |

### 验收 1 · 干净环境首次启动自动完成模型准备

用**空的 `user.home`** 起装好的程序（隔离到空目录 = 模拟「刚装好的新机器」），
只通过 HTTP 接口观察：

```
ok  程序起来了，本地服务可用
    模型状态：可用（READY）
ok  首次启动自动把模型装好了（状态：可用）
ok  模型版本：litemask-ner-zh-char-v3
ok  界面报出「支持人名识别」与「支持机构名识别」
ok  状态是「可用」，且是真的可用（模型已加载）
ok  模型装到了用户数据目录（…\empty-home\.litemask\models\ner\ner.onnx）
```

**全程没有终端**。模型是程序自己从**安装包里的已签名模型包**装上来的：
验签 → 原子换装 → 真的把 ONNX 模型加载一遍。
（「可用」不是「文件在」——`ModelManager.loadActive()` 失败会报成「损坏」，不会报成「可用」。）

### 验收 2 · 不依赖预装 Java / Node

产品自带 jlink 裁剪运行时；打包脚本用**裁剪后的 java** 跑能力自检：

```
ok  KeyFactory Ed25519（模型包验签要用）
ok  Ed25519 签名/验签
ok  AES/GCM/NoPadding（映射件加密）
ok  SecretKeyFactory PBKDF2WithHmacSHA256
ok  HttpsURLConnection（本地服务）
```

验收脚本本身只发 HTTP 请求，**没有调用任何装模型的命令**。

### 验收 3 · 合成文档，模型确实参与

文档（`合成文档.txt`）里同时有规则能认的（身份证号、手机号）和**只有模型能认**的（人名、机构名）：

```
本院受理的张伟明诉北京明诚科技有限公司买卖合同纠纷一案。
原告张伟明，身份证号11010519491231002X，手机13800138000。
被告北京明诚科技有限公司，法定代表人李静。
证人王海涛陈述：上述事实属实。
```

实际结果：

```
命中 6 行 / 6 个值：张伟明、北京明诚科技有限公司、11010519491231002X、13800138000、李静、王海涛
ok  规则类命中（身份证号）被脱敏
ok  人名被识别并脱敏（模型确实参与了）
ok  机构名被识别并脱敏（模型确实参与了）
ok  结果里标明「识别来源：本地人名与机构名识别模型」（NER 参与了这次脱敏）
ok  结果里没有「人名与机构名没有被脱敏」那句（模型确实参与了）
```

三个名字与一个机构名都被认出来了 —— 这是**模型参与**的硬证据，
不是「文件里有东西所以清单非空」。

### 验收 4 · 离线安装 / 损坏 / 签名不对

| 场景 | 结果 |
|---|---|
| **离线模型包**（用户只选一个文件） | `ok 离线模型包（用户只选一个文件）装得上` |
| **损坏的包** | `ok 坏包装不上，并且说清了原因：这个模型包装不上：文件有问题，无法安装。` |
| **签名不对的包** | `ok 签名不对的包装不上：新模型没装上，但当前这一版仍然可以正常使用。` |
| 坏包之后原来那份 | `ok 装失败之后原来那份模型仍然可用（没有把用户降级）` + `ok 装失败之后原来那份模型一点没变（原子性）` |
| 签名不对之后原来那份 | `ok 签名不对的包没有破坏原来那份模型` |
| **用户下一步** | `ok 给出了用户可以点的下一步：请点「重试」重新安装；仍不行就点「选择离线模型包」换一个文件。` |

**磁盘不足 / 中途中断**：这两类失败都落在「换装中途抛 IOException」这条路上，
由 `ModelPackageStore` 的原子换装保证**原来那份不受影响**（上面「原子性」两行就是它的实测）。
新增的两条回归测试：

- `装到一半失败原版仍可用`：造一个**签名过得去、但模型加载不了**的包 →
  验签过 → 进入安装 → 校验时失败 → 状态报「更新失败」，**原来那份仍然可用**。
- `换装中断后能恢复`：模拟「换装死在两次改名之间」（生效目录没了、历史里还有）→
  启动时自动把历史里那一版换回来，**不**报「未安装」。

（这两条是单元测试；本机没有能做「磁盘写满」的干净环境，如实标注见 §六。）

### 验收 5 · 更新失败后原版本仍能使用

单元测试 `更新失败原版仍可用`：先装一版，再拿一个**签名用不受信钥匙**的新版本去装 →
验签失败 → 状态报「更新失败」→ **原来那份仍然可用**（`m.isModelUsable()` 仍为 true）。

界面上这一态显示「更新失败，但当前这一版仍然可以正常使用」，并给出「重试」「恢复上一版本」。

### 验收 6 · 升级后模型、设置、用户数据保持正确

**从 1.0.0 升到 1.1.0**（1.0.0 是用 git worktree 从本仓库 HEAD 打出来的**真实旧版**）：

```
msiexec exit = 0            （不是 1638，也不是 1603）
LightMeter | 1.1.0 | C:\Users\zhang\AppData\Local\LightMeter\
app\models\ner-package\ 里有 litemask-ner-zh-char-v3.zip + .zip.sig
model sha256 BEFORE = FD18F27A35DB25ECA3EE8CAE3205040868D2F193369DF4352CDF396F8F5201EE
model sha256 AFTER  = FD18F27A35DB25ECA3EE8CAE3205040868D2F193369DF4352CDF396F8F5201EE
preserved = True
```

**从 1.1.3 升到 1.1.4（程序正在运行，发布件本身）**：

```
running: 2
jar IS locked
=== upgrade 1.1.3 -> 1.1.4 while RUNNING ===
msiexec exit = 0   elapsed = 8.1 s
after: LightMeter | 1.1.4
app processes now: 0
model preserved = True
应用日志：「检测到安装程序正在更新本程序，正在退出以完成升级。」
```

**升级时程序正在跑，安装照样成功** —— 用户不用找进程、不用执行命令。

> 这一条是本轮**最费劲**的一条：Windows Installer 启用 Restart Manager，
> 但它只能通过**窗口消息**请程序退出；本产品是控制台程序（没有窗口）→
> 它被判成「critical application」而**拒绝关闭**，于是升级报 1304/1603，
> 并留下一句「Close that application and retry」——把找进程的活儿推给用户。
> → 1.1.2 起，程序自己盯着安装目录 + 直接观察有没有带本产品名的安装器进程在跑，
> 一旦发现就**自己交还资源并退出**。

### 验收 7 · 普通用户能通过界面理解失败并恢复

- 状态区六种状态：未安装 / 正在安装 / 正在校验 / 可用 / 损坏 / 更新失败；
- 错误说明是**人话**（「文件有问题，无法安装。」「不是由本产品发布方签发的，来源不明或已损坏。」），
  **不出现** `--ner-model`、`model trust`、文件路径、堆栈、密钥；
- 每种失败都配一个用户能点的下一步；
- 技术细节进日志文件 `%LOCALAPPDATA%\.litemask\logs\litemask.log`，**不进界面**。

### 验收 8 · 未启用识别时必须持续提示，且要用户明确选择

模型不可用时：

- 页面顶部常驻「**当前未启用人名与机构名识别，结果需要人工处理。**」；
- 「开始扫描」按钮**要用户勾选「我已知晓本次结果需要人工处理」之后**才可点；
- 脱敏结果里也会带一句「**中文人名与机构名没有被脱敏。**」。

这一条有静态守卫（`WebUiTest.识别模型有入口`），保证它不会被静默删掉。

### 验收 9 · 本地处理不被破坏

- 模型包是**装在本机**的，推理走本地 ONNX Runtime；
- 文档处理全程在 `127.0.0.1` 上；
- **模型下载**：本版**没有**引入任何模型下载功能（发布方没有公开托管地址），
  因此不存在「下载时夹带文档/OCR 文本/身份映射」的可能。
  模型要么随安装包带来，要么由用户本地选一个离线包 —— **两条路都不出网**。

## 四、这一轮**修掉的真缺陷**（都是实测撞出来的）

| 缺陷 | 症状 | 根因 | 修法 |
|---|---|---|---|
| 同版本不同构建装不上 | MSI 报 1638 | jpackage 用「应用名 + 版本」推导 ProductCode，版本一样 → ProductCode 一样 | 版本号真实提升（1.0.0 → 1.1.4），UpgradeCode 保持不变 |
| 升级时程序在跑就失败 | MSI 报 1304/1603，且让用户自己去结束进程 | Restart Manager 对无窗口的控制台程序拒绝关闭 | `InstallWatcher`：程序自己看见安装器、自己让位 |
| `InstallWatcher` 第一版**根本不触发** | 升级仍然 1603 | 主循环先 `await` 一小时才去 `poll` → 第一条事件要等一小时 | 改成带超时地 `poll`；再加「有没有带本产品名的安装器进程在跑」作为第二个信号 |
| 换装被中断后界面说「未安装」 | 用户明明有一份能用的模型 | 换装是两次改名，中间死掉会让生效目录短暂不存在 | 启动时从历史里自动换回来（1.1.3 起） |
| 两个服务抢同一个端口 | 打包脚本把「第二次健康检查」打到了第一次上 | 两次起服务用了同一个端口与同一份日志 | 拆成两个端口、两份日志 |
| macOS 脚本里带空格的路径会被拆开 | 模型包名带空格时找不到 | `set -- $zips` 那种写法会按空格切词 | 逐行读，不做词分割 |
| PowerShell 脚本缺 BOM 时中文全乱码 | 判据恒假 | PowerShell 5.1 按 ANSI 读无 BOM 的 .ps1 | 所有含中文的 `.ps1` 保持 UTF-8 **带 BOM** |

## 五、**未验收**的部分（如实标注）

| 项 | 状态 | 原因 |
|---|---|---|
| **macOS 的 `.pkg` / `.dmg`** | **未验收** | 本机是 Windows，**没有 macOS 机器**。`tools/package-macos.sh` 已做对应改动（随附模型包进包、首次启动自动装模型的验收、体积报告），并做了 `bash -n` 语法检查，但**没有真机跑过**。**不以源码检查替代验收。** |
| **macOS 的目标架构与原生推理依赖核对** | **未验收** | 同上。Windows 侧的原生库预检（win-x64 必须带、osx-aarch64 必须不带）是**真跑过**的；macOS 侧没有。 |
| **代码签名 / 公证** | **无** | 没有 Apple 开发者证书，也没有 Windows 代码签名证书。安装包会显示「未知发布者」/ 需要在「隐私与安全性」里点「仍要打开」。**不要求用户关闭任何系统安全功能。** |
| **「磁盘写满」的整机实测** | **未实测** | 需要一块真的写满的盘。覆盖到的是**同一条代码路径**（换装中途抛 IOException → 原来那份不受影响），有单元测试，但**没有整机实测**。 |
| **浏览器端的点击操作** | **部分** | 本轮验收走的是 **HTTP 接口**（等价于点按钮），不是真人点浏览器。没有自动化浏览器。界面与接口的接线有静态守卫（`WebUiTest`）。 |
| **macOS / Windows 的浏览器下载映射件** | **未变** | 这一轮没有动映射件的加密与下载路径。 |

## 七、怎么复现这份验收

```powershell
# 1) 构建（默认跑测试）
powershell -ExecutionPolicy Bypass -File tools\package-windows.ps1 -ModelPackageDir dist

# 2) 装上
msiexec /i target\installer\LightMeter-1.1.4.msi /qn

# 3) 用装好的程序做验收（只走 HTTP，不碰命令行装模型）
powershell -ExecutionPolicy Bypass -File tools\acceptance-model.ps1 `
    -Exe "$env:LOCALAPPDATA\LightMeter\LightMeter.exe" -Port 19911
```

第 3 步的期望输出末尾是：`验收结果：通过 18，失败 0`。
