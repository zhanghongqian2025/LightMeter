## 图表是 pptx 的要害

这一点与 xlsx 相反，值得单独说明：

- **xlsx 的图表**：数据源指向单元格，Excel 打开时会重算，所以缓存值只是"上次算的快照"，
  漏掉它风险较低（我把它列为已知缺口）。
- **pptx 的图表**：数据**内嵌在文件里**，PowerPoint 打开时**不会**重算。
  所以 `<c:numCache>` 里的那个值**就是屏幕上显示的那一份**——漏掉它等于把身份证
  留在坐标轴标签上。

代价：把数值缓存换成占位符后，PowerPoint 会提示"数据无效"，需刷新图表。
这是脱敏必须付的代价，因此**单独计数并在 CLI 明确提示**，不默默发生。

`<c:v>` 还要区分两种缓存：`<c:strCache>`（字符串，改了不影响渲染）与
`<c:numCache>`（数值，改了会提示刷新）。判断要看**祖父节点**——
层级是 `numCache → pt → v`，看父节点会判错（这正是本阶段踩的一个 bug）。

## 本阶段修掉的缺陷

`isNumericCache` 判断 `<c:v>` 是否在数值缓存里时查了**父节点**，
而真实层级是 `numCache → pt → v`，导致数值缓存从未被计数——
报告说"0 个图表数值缓存已脱敏"，而实际改了 1 个。
**症状是计数不对而不是脱敏不对**，很容易被当成无害的统计 bug 放过。
判据：凡是"报告里的数字"和"实际发生的事"不一致，先怀疑报告本身。
