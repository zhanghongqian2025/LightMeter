## 复核时抓到的构建污染事故（2026-10-14 晚）

复核阶段重跑测试发现 2 条 `RedactionRoundTripTest` 失败，**但源码是好的**。用 CFR 反编译
`target/classes` 才发现，class 里的构造器被编译成了：

```java
Matcher matcher = Pattern.compile("(?!)").matcher(sourceText);   // 永不匹配的变异体
```

这正是对照实验第⑤项的变异。事故链条：

1. 脚本用 `cp` 备份源文件 → `.bak` 的 mtime 是**变异前**的时刻；
2. 变异体编译进 `target/classes`，class mtime = 变异**后**；
3. `mv .bak 源文件` 还原后，源文件 mtime **比 class 更旧**；
4. Maven 增量编译判定「无需重编」，此后所有 `mvn test` 都在跑变异体；
5. 红灯看起来像代码缺陷，其实是**构建产物脏了**——正是「红灯原因必须正确」要防的形态。

删除 `target/classes` 全量重编后 383 条全绿。连带发现：上一轮打进 `target/desens-core.jar`
的也是变异 class，端到端演示跑的是脏 jar。

已做的加固（`tools/control-experiment.sh`）：

- 每次变异前、还原后都强制丢弃 `target/classes`（离线环境 `mvn clean` 不可用，
  `maven-clean-plugin` 未进本地仓库）；
- 脚本开头检测并中止于残留 `.bak`；
- **收尾新增基线复核**：全部实验跑完后必须重新编译并断言绿灯、无残留备份，
  否则整场实验判失败——上一轮就是缺这一步才把脏 class 带进后续开发。

## 测试数字的取数陷阱

`RuleSampleTest` 用 `@TestFactory` 动态测试（360 条），surefire 会把每个 `Run N` 单独列出，
此时末尾的汇总行是**容器计数**而非用例数——实测「360 条动态用例挂 10 条」时汇总行显示的是
`Tests run: 24, Failures: 1`。直接信它会报出假数据。

脚本改为解析**每个测试类那一行**（`… Time elapsed … -- in <类名>`），该行在动态测试下仍准确：

```
破坏① -> EngineBehaviorTest 8 用例 失败2
破坏② -> RuleSampleTest 360 用例 失败10
破坏⑤ -> RedactionRoundTripTest 8 用例 失败2
基线   -> 四个测试类合计 383 用例 失败0
```

同时基线复核会交叉校验：退出码为 0 但仍报出失败/错误 ⇒ 判失败（证据自相矛盾不许通过）。

## 本阶段修掉的真实缺陷

1. `document_no` 正则**字符类未闭合**，整条规则从未编译成功（7 条样本失败暴露）。
2. `case_number` 漏报 5 位流水号案号，且把「（2024）民初123号」（缺法院代字）误判为案号。
3. `LUHN` 放行全同数字（`0000…` 校验和恰好为 0）。
4. 统一社会信用代码 `sum % 31 == 0` 时检查位索引越界，抛 `StringIndexOutOfBoundsException`。
5. `qq_number` / `passport` 引导词大小写敏感、`QQ号码` 不识别。
6. `vin` / `ip_address` / `telephone` 边界不足，会从 `abc6222…`、`192.168.1.1a` 里切出片段。
7. 统一社会信用代码未要求含字母，任意 18 位纯数字串有约 1/31 概率蒙混过关。

## 已知边界（M0 明确不做）

- **姓名 / 地址 / 机构名不脱敏**：依赖 NER，属 M3。这是当前与目标产品最大的差距。
- **金额类不脱敏**（阿拉伯数字金额、中文大写金额）：M1 补规则。
- 仅支持纯文本，**不支持 docx/xlsx/pptx/pdf/ofd**：M1。
- 无本地服务与 Web 界面：M2。
- 无 Windows / macOS 安装包：M4。
