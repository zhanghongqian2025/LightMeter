## 一、六格式处理边界矩阵

判据口径（先说清「验过」是什么意思）：
- **验过** = 用**装完之后**的那个 exe（`%LOCALAPPDATA%\LightMeter\LightMeter.exe`）跑出来的，
  并用**独立于产品实现**的校验器复核；
- 校验器：`tools\verify_ooxml.py`（全包字节级扫描 + 往返）、
  `tools\verify_ofd.py`（字节级扫描 + XML 可解析 + TextCode 文字往返）、
  `tools\E2ePdfSample.java check`（PDFBox，独立读取器）。
- **不支持**一栏是产品**明确做不到**或**刻意不做**的地方，不是「没测过」。

### TXT

| 敏感信息位置 | 处理方式 | 验证结果 | 不支持/不可逆 |
|---|---|---|---|
| 正文任意位置（身份证、手机号、邮箱、银行卡、统一社会信用代码等规则型标识符） | 逐条替换为占位符 `<身份证1>` 之类，同值同符 | ✅ 脱敏件里搜不到原值；还原件与原件**逐字相同** | 无 |
| 换行 | 原样保留，不做归一化 | ✅ 往返逐字一致即含换行 | 无 |

### DOCX

| 敏感信息位置 | 处理方式 | 验证结果 | 不支持/不可逆 |
|---|---|---|---|
| 正文段落（`w:t`） | 段落内跨 run 拼接后替换，避免碎片漏脱 | ✅ `verify_ooxml.py check` 全包无残留 + `roundtrip` 通过 | 无 |
| 表格单元格 | 与正文同一条代码路径（DOM 深度优先） | ✅ 同上 | 无 |
| 页眉页脚、脚注尾注 | 同上（每个 XML part 都遍历） | ✅ 同上 | 无 |
| 文本框（`w:txbxContent`） | 同上 | ✅ 同上 | 无 |
| 批注 | 同上 | ✅ 同上 | 无 |
| 工作表名类元数据 | docx 无 | — | — |
| **域代码（`w:instrText`）** | **不处理** | — | ⚠️ 域指令本身不动（改了会破坏域）。**域目标 URL 里可能带敏感值** —— 已知缺口，见下表「已知未覆盖」 |
| 文档属性（作者、公司、修改时间） | 整体清空 | ✅ 全包扫描无残留 | ⚠️ **不可逆**：原值从未保存，还原带不回来 |
| 嵌入对象（图片等二进制部件） | 不动 | ✅ 全包字节级扫描确认无残留 | ⚠️ 二进制部件里的元数据不处理 |
| 关系 URL（`.rels` 里的 Target） | 走同一套替换 | ✅ 同上 | 无 |

### XLSX

| 敏感信息位置 | 处理方式 | 验证结果 | 不支持/不可逆 |
|---|---|---|---|
| 共享字符串（`xl/sharedStrings.xml`） | 替换（同值同符，引用它的单元格一起变） | ✅ `verify_ooxml.py` 全包无残留 + `roundtrip` 通过 | 无 |
| 内联字符串（`t="inlineStr"`） | 同上 | ✅ 同上 | 无 |
| 公式缓存结果（`t="str"` 的 `<v>`） | 替换，公式本身保留 | ✅ 同上 | 无 |
| 数值单元格（`622202020202020207` 这类） | 转成内联字符串 | ✅ 同上 | ⚠️ 单元格类型会变（这是必须的） |
| 工作表名 | 替换（Excel 允许 `< >`） | ✅ 同上 | 无 |
| 定义名称、批注、文档属性 | 替换 / 清空 | ✅ 同上 | ⚠️ 文档属性清空不可逆 |
| **图表缓存值（`xl/charts/chart*.xml` 的 `<c:pt><c:v>`）** | **不处理** | — | ⚠️ Excel 打开时按源单元格重算，显示层不泄漏；但**直接解压 xlsx 仍能看到旧缓存值** —— 已知缺口 |

### PPTX

| 敏感信息位置 | 处理方式 | 验证结果 | 不支持/不可逆 |
|---|---|---|---|
| 幻灯片文本（`<a:t>`） | 跨 run 拼接后替换 | ✅ `verify_ooxml.py` 全包无残留 + `roundtrip` 通过 | 无 |
| 备注页、母版、版式 | 同上（同一遍历路径） | ✅ 同上 | 无 |
| **图表数据缓存（`<c:v>`）** | **替换** | ✅ 同上 | ⚠️ PowerPoint 会提示「数据无效」直到刷新图表 —— 脱敏必须付出的代价 |
| 文档属性 | 清空 | ✅ 同上 | ⚠️ 不可逆 |

### PDF

| 敏感信息位置 | 处理方式 | 验证结果 | 不支持/不可逆 |
|---|---|---|---|
| 页面内容流里的可见文字 | 解码内容流 → 替换 → 重写；用 TJ 位移补偿保版面 | ✅ `E2ePdfSample check`（PDFBox 独立读取器）全部通过 | 无 |
| 表单 XObject | 同上 | ✅ 同上 | 无 |
| 版面（后续文字按原位摆回） | 位移补偿 | ✅ 同上 | ⚠️ 令牌与原值宽窄不同，个别情形会留空隙（不重叠、不错位） |
| Info / XMP 元数据 | 清空 | ✅ 同上（PDFBox 独立读取器确认无残留） | ⚠️ 不可逆 |
| 批注与批注外观 | 清理 | ✅ 同上 | ⚠️ 不可逆 |
| ActualText / Alt（无障碍替代文本） | 清理 | ✅ 同上 | ⚠️ 不可逆 |
| 表单值、书签、附件、关联文件 | 清理 | ✅ 同上 | ⚠️ 不可逆 |
| **字体缺 ToUnicode（解不出字符）** | **直接拒绝处理并说明原因** | ✅ fail-closed 行为有单测覆盖 | ⚠️ 不是「处理了」，是「停下来并报错」 |
| **纯扫描件（无文本层）** | 检不出文本 → 零命中 | ⚠️ 见「已知未覆盖」 | ❌ **本轮不覆盖**：图片像素里的敏感信息本工具不处理 |

### OFD

| 敏感信息位置 | 处理方式 | 验证结果 | 不支持/不可逆 |
|---|---|---|---|
| 正文（`Pages/Page_N/Content.xml` 的 `TextCode`） | 逐部件深度优先遍历替换 | ✅ `verify_ofd.py scan` 字节级无残留 + `check-roundtrip` 通过 | 无 |
| 模板页（`Tpls/`） | 同上 | ✅ 同上 | 无 |
| 批注与水印（`Annots/`） | 同上 | ✅ 同上 | 无 |
| `TextCode/@Text` 关键字属性 | 同上 | ✅ 同上 | 无 |
| `DocInfo`（`OFD.xml` 的 `CustomData`、`Author`、`Creator`） | `CustomData` 替换；`Author`/`Creator` 清空 | ✅ 同上 | ⚠️ Author/Creator **不可逆** |
| 附件条目名（`Attachs/13800138000_申请书.pdf`） | 条目名与 XML 引用一起改；**文件名用全角令牌形态 `［手机号1］`** | ✅ 校验器确认「附件条目已改名、内容保留」 | ⚠️ Windows 文件名不允许 `< >`，全角形态是为此；映射里同步登记，**还原能换回原名** |
| 签章部件与引用 | 移除 | ✅ 校验器确认「签章部件与引用均已移除」 | ⚠️ 不可逆 |
| **跨 `TextObject` 拼接** | **不做** | — | ⚠️ OFD 是绝对定位版式，跨对象合并只能靠几何启发式，多栏发票会误拼。宁可少认 |

### 已知未覆盖（各格式共同）

| 项 | 状态 | 说明 |
|---|---|---|
| 扫描件 / 图片里的像素文字 | **不处理** | 本轮不开发 OCR 或图像脱敏。零命中必须与「未识别」区分开看，**不能把扫描件当脱敏件交付** |
| 带 OCR 隐藏文本的扫描件 | **不处理** | 同上；隐藏文本层会被处理，但图像本身没变 |
| 文字与图片混合页面 | **部分** | 文字层被处理；图片部分不处理 —— 交付前必须人工复核 |
| DOCX 域代码里的 URL | **不处理** | 已知缺口（见 DOCX 表） |
| XLSX 图表缓存值 | **不处理** | 已知缺口（见 XLSX 表） |

## 二、本轮在真 Windows 上修掉的真实缺陷

以下每一条都是**在 Windows 11 真机上跑出来的**，不是推测：

| # | 缺陷 | 后果 | 修在哪 |
|---|---|---|---|
| 1 | `PrivateFile` 在 Windows 上**静默不设权限** | 映射件/上传原件同机任何账户可读 | `core/PrivateFile.java` 改走 Windows ACL，ACL 不可用时 fail-closed |
| 2 | 目录 ACL 缺继承标志 | 目录里新建的文件拿到**空 DACL**（Windows 语义 = 人人可读） | 同上，`FILE_INHERIT` + `DIRECTORY_INHERIT` |
| 3 | `CliHelpEverywhereTest` 在 Windows 上死锁 | 整条测试挂死 | `CliProc`：两条流同时排空 |
| 4 | stdout 编码跟系统本地代码页走 | 中文系统 GBK、其它 locale cp1252 → 同一份产品两平台编码行为不同 | `jvm.args` 显式 UTF-8；`redact -` 直接写 UTF-8 字节 |
| 5 | 两个 launchd 测试类在 Windows 上整类红 | 12+12 条用例一条没跑 | 去掉无关的 POSIX 权限依赖 |
| 6 | OFD 附件名里的令牌带 `< >` | 脱敏件在 Windows 上**连解包都做不了** | 文件名用全角形态 + 映射同步登记 |
| 7 | `package-windows.ps1` 的 app-image EXE 路径写错 | 脚本跑不到第 4 步 | 打完真的去找一次 |
| 8 | 原生命令写 stderr 被 PowerShell 当致命错误 | 脚本在读 Java 版本号第一步就死 | `Invoke-External` |
| 9 | `jlink` 模块集**缺 `jdk.crypto.ec`** | 装好的产品**模型包一件都装不上**（Ed25519 KeyFactory 不在 java.base） | 模块集补 `jdk.crypto.ec` + 新增能力自检守卫 |
| 10 | 判定内核参数名 `$Input` 撞自动变量 | 绑定被静默忽略 → 装完再验永远读不到输入文件 | 改名 `$InputPath`（保留 `-Input` 别名） |
| 11 | e2e 脚本 `& $checkPath` 变量名打错 | 判定内核根本没被调用 | 改名 + 改用哈希表 splat |
| 12 | 签名私钥在 Windows 上权限没收紧 | 同机任何账户读得到**发布私钥** | 改走 `PrivateFile.write` |
| 13 | `reg.exe` 会**吃掉** `/d` 里的双引号 | 路径无空格 → 存进去的值少引号，自检判失败（明明能跑）；路径**有空格** → `reg add` 直接报错，**自启根本装不上** | `WindowsRunKey.addCommand` 把引号转义成 `\"`；假的 reg.exe 也按真实行为建模 |
| 14 | 界面**只能排除误报，不能补上漏检** | 规则认不出来的名字/代号（当事人名、内部案号）就落在「零命中」里，而那些字明明白白在文档里 —— 人工复核只剩一半能力 | 新增 `core/UserTerms` + `POST /api/terms` + 界面「补充敏感词」入口：补的词接进**现有引擎**重扫，出现在命中清单里、可排除、进映射 |
| 15 | 零命中只报「0 处」 | 「没命中」与「**根本没找过**」（人名识别没开/文件没有文字层）对用户意义完全不同，都显示成零命中 → 猜错就以为干净发出去了 | 零命中**分四种**说清；没有文字层的 PDF **拒绝导出**成脱敏件（那份文件与原件逐字相同） |
| 16 | 裁剪运行时缺 `--add-opens java.base/java.nio` | PDFBox 每次都抛 `InaccessibleObjectException`（用户以为工具坏了），且 unmap 失效 → 大 PDF 内存降不下来 | `jvm.args` 补 `--add-opens=java.base/java.nio=ALL-UNNAMED`（**必须单 token 形式**：jpackage 逐行传参，写成两段配不上） |

> 第 13 条的来由：本轮跑 `tools\e2e-windows-autostart.ps1` 时，产品**自己**先发现了它
> ——「写进注册表的内容与预期不一致 —— 这样开机自启不会工作，不能当成功」（退出码 1）。
> 也就是说这条链路**是 fail-closed 的**（不会假装成功），但功能确实是坏的。
> 修法经真机实测：转义后 `reg add` 退出码 0，注册表里存的是
> `"C:\...\LightMeter.exe" serve --no-browser --port 8090`（带引号），与预期逐字相同。
