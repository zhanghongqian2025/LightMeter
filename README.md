# LightMeter 轻量单机脱敏工具

> 公开源码版本：包含程序、测试与构建工具；本机合同样例、脱敏映射、恢复原文和安装产物单独保管。

拖入 docx / xlsx / pptx / pdf / ofd / txt，得到脱敏文件与可还原的映射。
**文档内容零外发** —— 没有云端、没有遥测，脱敏全部在本机完成。
这一条现在有**会红的检查**兜着：封网沙箱里跑六种格式的脱敏 + 还原往返（系统调用层封网），
外加一道扫常量池的出网白名单标尺；两组负控制证明这条检查**确实会咬**（细节见 M4 §三十）。

对照参考产品：元典脱敏 2.2.10（原版 pkg 820MB / exe 959MB），
本项目核心包 **75.60 MiB ≈ 79.28 MB**（含 AI 模型包，预算 90MB）。

## 一、怎么装、怎么用

### 怎么装（macOS 两种形态）

| 形态 | 怎么装 | 适合谁 |
|---|---|---|
| `.pkg` | 双击安装器，跟着提示装 | IT 统一分发 |
| `.dmg` | 打开镜像，把 `LightMeter.app` 拖进「应用程序」 | 同事自己装 |

两种形态里跑的是**同一套东西**（同一个 fat jar + 同一个裁剪运行时），
区别只在装法与卸载方式：`.pkg` 走系统卸载流程，`.dmg` 是拖到废纸篓。

**人名与机构名的识别模型已经随包带上**，装完打开就能用，**不需要另外装**。
程序在第一次启动时会自己把模型准备好（校验签名 → 原子安装 → 真的加载一遍），
界面上会显示「人名与机构名识别已就绪」。见 §一「识别模型：装好就有」。

每个平台的包**只带自己那套**推理原生库（macOS 包里不会有 Windows 的，反之亦然）。
打包那一步会当场核对：**该带的没带、或混进别的平台的，打包直接失败**——
不会出现「装得上、一跑模型才炸」的包。

### 怎么装（Windows x64）

| 形态 | 怎么装 | 适合谁 |
|---|---|---|
| `.msi` | 双击 `LightMeter-1.1.4.msi`，跟着提示装 | **首选**；普通用户即可安装，不需要管理员 |
| `.exe` | 双击 `LightMeter-1.1.4.exe`（自解压安装器，内部仍是同一个 MSI） | 不想用 MSI 的场合 |

- 装到**每个用户各自的目录**：`%LOCALAPPDATA%\LightMeter\`，
  不写系统目录、**不需要管理员权限**、不影响同一台机器上的其它用户。
- **升级时不用先退出程序**：程序自己会看见「安装器来了」，把资源交还之后自己退出，
  安装器接着完成覆盖。**不用找进程、不用执行任何命令**。
  （以前这一步会报 1304/1603，还要用户自己去结束进程——那条路已经去掉了。）
- 卸载：控制面板「已安装的应用」里卸 `LightMeter`，
  或 `msiexec /x {产品码} /qn`。卸载**不删**你保存的原件、脱敏件与映射件——
  那些是你的文件，不是应用数据。
- **不装 Java 也能跑**：包里自带裁剪过的运行时（`runtime\`）。
- **升级保留你的模型、设置与用户数据**：它们在 `%LOCALAPPDATA%\.litemask\`，
  与程序目录分开，升级不会动它们。

**人名与机构名的识别模型已经随包带上**，装完打开就能用，**不需要另外装**。
见 §一「识别模型：装好就有」。

### 识别模型：装好就有

以前模型是**单独分发**的：装完程序还要再敲 `model install`、`model info`——
那不是「少一个功能」，是**产品没交付完**。现在：

1. **模型随安装包分发**（一个已签名的模型包 + 它的签名）。
2. **第一次启动时程序自动准备好它**：
   - 检查是不是已经有兼容且可用的模型；
   - **校验签名与摘要**（确认它确实来自发布方，而不是被人改过的）；
   - **原子安装**到当前用户的数据目录（失败时保留你原来那份能用的）；
   - **真的把模型加载一遍**（确认推理引擎能跑，不只是「文件在」）。
3. 界面顶部显示 **「人名与机构名识别已就绪」**。

**全程不需要打开终端**，也不需要装 Java、Node 或配环境变量。

界面上那一栏还提供：

| 情况 | 你会看到 | 你可以做什么 |
|---|---|---|
| 还没准备好 | 「正在安装模型」/「正在校验」 | 等一下就好（进度是真的操作结果） |
| 已就绪 | 「人名与机构名识别已就绪」+ 当前模型版本 | 「更新模型」「恢复上一版本」 |
| 装不上 / 坏了 | 一句人话 + 下一步该做什么 | 「重试」「选择离线模型包」 |
| 更新失败 | 「更新失败，但当前这一版仍可正常使用」 | 「重试」「恢复上一版本」 |

**「选择离线模型包」**：如果你拿不到在线包，可以选一个**离线模型包文件**
（一个 `.zip`，里面已经带着模型与它的验证材料）。
用户只需要选**这一个**文件——不需要自己去找 `.sha256`、`.sig` 或公钥。

> **离线包不是随便一个 zip**：它里面必须装着发布方签过名的模型包。
> 程序在安装那一刻会验签，验不过就**不装**，并说明原因。

### 双击（图形界面）

双击 `LightMeter.app` 会启动本地服务并自动打开浏览器界面。
Windows 上同理：双击 `LightMeter.exe`（安装后在「开始菜单 → LightMeter」里）。
服务**只绑 127.0.0.1**，同一网段的其它机器连不上；每次启动生成一次性会话令牌。

扫描完是一张**命中清单**，**默认全脱敏**；勾选你要**保留**的行，再点「应用」。

- 勾**整行** = 保留这个值在文档里的**所有**出现处。
- 同一个值**出现不止一次**时，每处位置前面还有一个**小勾选框**：
  勾上它 = **只保留那一次出现**，同一个值的其它出现处照常脱敏。
  位置说明形如「第 2 页 · 文本块 5」「偏移 120–134」。
  出现次数多的时候，位置清单默认只显示前 3 条，点「展开全部（共 N 处）」看全部 ——
  **折叠起来的那几处照样能勾**（折叠的是显示，不是「能不能选」）。
- 整行勾选与逐处勾选**互斥**：勾了整行，这一行的逐处勾选会置灰；
  反过来勾了某一处，这一行的整行勾选会取消。

**补充敏感词（人工补漏）**

内置规则只认**有固定形态**的东西（身份证、银行卡、手机号…）。
但卷宗里有大量**没有固定形态**的敏感信息：某个当事人名字、某个内部案号、某个代号。
规则认不出来 → 清单上零命中 → 而那些字**明明白白就在文档里**。

命中清单下方有一个「**补充敏感词**」输入框：把你知道的词填进去（多个用逗号或换行分开），
点「加入并重扫」。补的词：

- 会**出现在上面的命中清单里** —— 所以你仍然能勾掉它（那也可能是个误伤）；
- 会真的被脱敏，并进映射件、可以还原；
- **只对这一份文件有效**：它不是全局规则，也不影响下一份文件。

> 补的词至少 2 个字：一个字的词会命中全文的每一个字，那不是脱敏，是把文件毁掉。

**零命中要说清是哪一种零**

「零命中」这四个字对用户至少有三种完全不同的含义，界面会分别说清：

- **文件里没有文字层**（扫描件/纯图片）→ 图片里的内容**没被处理**；
- **规则没命中，且人名识别没开** → 人名**根本没被找过**；
- **规则没命中**（识别已开）→ 真的没命中，但**没有固定形态的名字仍可能漏**，请人工复核。

### 命令行

同一个可执行文件在终端里是完整 CLI：

```bash
LightMeter redact 合同.docx 证据.xlsx 讲稿.pptx
LightMeter restore 合同.redacted.docx --map 合同.docx.redacted.map.json
LightMeter rules                      # 查看规则库
LightMeter serve --no-browser         # 只起服务不开浏览器
LightMeter serve --max-upload-bytes 52428800   # 把单份上传上限调到 50MB（默认 256MB）
LightMeter serve --print-token        # 把会话令牌打到 stdout（排障用，默认不打）
LightMeter redact 合同.docx -o 脱敏件.docx     # 指定输出路径（-o / --output）
LightMeter redact 合同.docx --rules 我的规则.json  # 用自己的规则文件
LightMeter redact -                   # 从标准输入读，结果打到标准输出
LightMeter autostart install          # macOS / Windows：开机登录后自动起本地服务
LightMeter autostart status           # 看装没装、进程号、配置在哪
LightMeter autostart uninstall        # 卸掉自启（macOS 先从 launchd 卸下；Windows 删注册表值）
```

几个不写出来就会踩到的开关：

| 开关 | 口径 |
|---|---|
| `-o` / `--output 输出` | 指定脱敏件写到哪里；不写就写在原文件旁边，命名规则见下面「输出命名」 |
| `--rules 规则.json` | 用自己的规则文件；不写就用内置规则库（`rules` 子命令也认这个开关） |
| `--print-token` | `serve` 把当次启动的会话令牌打到 stdout；默认不打印（浏览器打开首页时由服务端注入），排障时用 |
| `--task-timeout 毫秒` | `serve` 单个任务的处理时限；`0` 表示不设时限，默认 30 分钟 |

每个子命令都有**自己的** `--help`，只讲它自己：

```bash
LightMeter --help            # 顶层：全部命令与开关的总览
LightMeter redact --help     # 只讲 redact
LightMeter model --help      # 只讲 model
```

`--help` **只打印用法，什么都不做** —— 不会脱敏、不会起服务、不会动开机自启。
开关名拼错了会当场报出来，并告诉你是不是想写另一个：

```
$ LightMeter redact 合同.docx --ouput 合同.docx
错误: 未知开关: --ouput（你是不是想写 --output？）
```

> 完整开关清单以 `LightMeter --help` 为准；本文与 `--help` 的一致性由
> `tools/e2e-cli-help.sh` 每次构建后自动核对（两块缺一块就报错）。
> 「每个子命令的 `--help` 都成立、且什么都不做」由
> `tools/e2e-cli-help-everywhere.sh` 每次构建后自动核对。

#### 映射件加密（可选）

映射件里存着**原值**——它是还原的唯一依据。默认它写成明文，
但权限一律收紧到 `600`（同机器上别的用户读不到）。
要让它**读不出来**，加一个口令：

```bash
# 口令从环境变量取。不要直接写在命令行里：
# 命令行会进 shell 历史，也会出现在 ps 的输出里。
export LITEMASK_MAP_PASS='你的口令'

LightMeter redact 合同.docx --map-pass-env LITEMASK_MAP_PASS
LightMeter restore 合同.redacted.docx --map 合同.docx.redacted.map.json \
  --map-pass-env LITEMASK_MAP_PASS
```

四种口令来源，**只能选一个**：

| 开关 | 口径 |
|---|---|
| `--map-pass-env 变量名` | 从环境变量取 |
| `--map-pass-file 文件` | 取文件**第一行** |
| `--map-pass-stdin` | 取标准输入**第一行** |
| `--map-pass-prompt` | 交互提示（不回显；没有终端时直接报错） |

映射件写成加密封装件（`litemask-sealed-map` v1）之后：

- 文件里**没有原值**（原文、Base64、无补位 Base64、hex 四种形式都查不到）；
- 还原时**必须**给同一个口令——不给会直接报错退出（退出码 2），
  **不会**「静默什么都不替换」；
- **口令没有找回**：忘了口令，这份映射件就废了。

> 封装格式、为什么用 AEAD 而不是「加密 + 校验和」、以及权限是怎么收紧的，
> 见 `docs/M4-阶段状态.md` §二十四。

#### 界面上给映射件设口令

浏览器界面（`http://127.0.0.1:8090/`）的**复核**卡片里有一个
「映射文件口令（可选）」输入框：

| 界面上怎么做 | 拿到的东西 |
|---|---|
| 输入框**留空** | 映射件是明文（权限 `600`），行为与从前完全一致 |
| 输入框**填了口令** | 映射件是**加密封装件**（`litemask-sealed-map` v1），文件里没有原值 |

填了口令之后，下载卡片上会出现一句「映射件已加密」，
并提示用 `restore --map --map-pass-env` 还原。
**口令用完就从输入框里清掉**——不会带到下一个文件上。

界面封的映射件**命令行也认**：

```bash
export LITEMASK_MAP_PASS='你的口令'
LightMeter restore 合同.redacted.docx --map 合同.docx.redacted.map.json \
  --map-pass-env LITEMASK_MAP_PASS
```

> 界面侧口令的完整口径、两种「没给口令」的语义、以及这一块的已知限制，
> 见 `docs/M4-阶段状态.md` §二十五。


#### 开机自动启动（macOS / Windows）

```bash
LightMeter autostart install --port 8090
LightMeter autostart install --app /Applications/LightMeter.app --port 8090
```

装一次以后，**登录系统后本地服务自动起来**，不用再手动双击。
两边是**同一个子命令**，机制各用各的。

三个选项：

| 开关 | 口径 |
|---|---|
| `--app 路径` | 程序位置（macOS 是 `.app` 目录；Windows 是 `LightMeter.exe` 或含它的目录）。不写就按当前运行的程序位置推断；推断不出来时会要你显式指定 |
| `--port 端口` | 固定端口（默认 8090） |
| `--label 标识` | 服务标识（macOS 是 launchd 的 label，Windows 是注册表值名；默认 `com.litemask.lightmeter`） |

**macOS**（LaunchAgent）：

- 配置写在 `~/Library/LaunchAgents/com.litemask.lightmeter.plist`，
  日志在 `~/.litemask/logs/serve.out.log` 与 `serve.err.log`。
- 服务崩了会自己回来（最短 10 秒后重试一次）。
- 端口被别的程序占着时，它会每 10 秒重试一次；端口腾开后自动就位
  （**不会**一直重试到机器重启）。
- `status` 只看 launchd 认不认这个服务，**不看端口通不通**——
  想确认能不能真的对外服务，请打 `http://127.0.0.1:8090/api/health`。

**Windows**（注册表 `Run` 键）：

- 值写在 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，
  值名与 macOS 侧共用同一个（默认 `com.litemask.lightmeter`）。
  用当前用户（HKCU）而不是本机（HKLM）：HKLM 要提权，普通用户装不上。
- 装完会**读回来逐字核对**；对不上直接报失败并打印「预期 vs 实际」——
  宁可报装不上，也不要留一个装上了却起不来的值。
- **`Run` 键没有自愈**：服务崩了不会自己回来（这是与 macOS 侧最大的差别）。
- **真 Windows 上还没验过**：注册表写入与引号转义目前只有微软文档与推理支撑。

### 输出命名

| | 规则 | 例子 |
|---|---|---|
| 脱敏件 | `<基名>.redacted<原后缀>` | `合同.docx` → `合同.redacted.docx` |
| 映射 | `<原文件名>.redacted.map.json` | `合同.docx` → `合同.docx.redacted.map.json` |
| 还原件 | `<基名>.restored<原后缀>` | `合同.redacted.docx` → `合同.redacted.restored.docx` |

映射名与脱敏件名**故意不一样**：映射从**输入名**派生，
所以对同一份文件脱敏两次不会互相覆盖。

## 二、中文人名与机构名识别（NER）

**普通用户不需要读这一节**：模型已经随安装包分发，程序在第一次启动时自动把它装好，
界面上显示「人名与机构名识别已就绪」。见 §一「识别模型：装好就有」。

这一节是给**需要自己管理模型**的人看的（排障、换模型、离线安装）。

模型包**随程序分发**，但它的**安装**仍然要过验签——签名是在**安装那一刻**被验的，
不是「发布时验过一次」。

| 情况 | 表现 |
|---|---|
| 还没准备好 | 界面显示「正在安装模型」/「正在校验」，并**持续提示**「当前未启用人名与机构名识别，结果需要人工处理」 |
| 装不上 / 损坏 | 界面显示**一句人话** + 下一步该做什么，**不会**谎称「已就绪」 |
| 正常 | 人名→`<人名1>`，机构名→`<机构名1>`，并进入还原映射 |

查找顺序：`--ner-model <目录>` > 环境变量 `LITEMASK_NER_MODEL` >
`<程序目录>/models/ner` > `~/.litemask/models/ner`

> **降级必须由用户明确选择**：模型不可用时，规则识别（身份证、银行卡、手机号…）
> 仍然照常工作，但界面会一直挂着那句提示，并且要用户**勾选确认**才让开始扫描。
> 「默认降级之后仍宣称脱敏完整」是这个工具最不能犯的错。

### 装模型包（命令行）

模型包的原始形态是三个文件：`litemask-ner-zh-char-v3.zip`（本体）
+ 同名 `.zip.sha256`（摘要）+ 同名 `.zip.sig`（**签名**）。
命令行装法只认**前两个挨着放**（签名必须与包并排，验签是按「同名 + .sig」找它的）：

```bash
LightMeter model install litemask-ner-zh-char-v3.zip     # 装到 ~/.litemask/models/ner
LightMeter model install litemask-ner-zh-char-v3.zip --to /某个/目录
LightMeter model info                                    # 报当前会用的是哪个模型包
LightMeter model verify /某个/模型包目录                  # 验一份目录能不能用（不安装）
LightMeter model list                                    # 列当前生效的与保留的历史版本
LightMeter model rollback                                # 退回上一个版本
LightMeter model rollback <版本键>                        # 退回指定的历史版本
LightMeter model remove <版本键>                          # 删掉一个版本
```

`install` 的行为：

- **先验签，再校验，再换装**：前一步不过就**原样不动**，并说明卡在哪一环；
- **换装是原子的**：装失败**不会**毁掉你原来那份能用的模型包；
- **按不受信任的输入处理**：越界条目（`../`）、反斜杠条目、绝对路径条目一律拒，
  条目数与解压总字节数有上限（防 zip 炸弹）；
- 装完**立刻生效**——下一次运行就会自动用上（`model info` 会报出来）；
- **换下来的旧版本会留着**（放在 `~/.litemask/models/ner.versions/`），
  新版本不合适时用 `model rollback` 退回去。

### 离线安装：用户只选一个文件

给不方便联网的人准备的**单文件**离线包：它是一个 zip，里面装着模型包与它的签名。
用户只需要在界面上点「选择离线模型包」并选中**这一个文件**。

```bash
# 造一个离线包（发布方做这一步）
python3 tools/package_offline_bundle.py \
    --model dist/litemask-ner-zh-char-v3.zip \
    --out dist/LightMeter-离线模型包-litemask-ner-zh-char-v3.zip
```

界面上的「选择离线模型包」与命令行 `model install` 用的是**同一套**验签与换装代码，
所以两条路的判定完全一致。

### 下载模型包

模型包是**独立分发**的，「从哪儿拿」是另一件事。工具这一侧做的是：

```bash
LightMeter model download https://example.com/litemask-ner-zh-char-v3.zip
LightMeter model download https://example.com/xxx.zip --sig-url https://example.com/xxx.zip.sig
```

一条命令走完「取包 → 验签 → 装上 → 生效」：

- **只走 http/https**，重定向最多跟 5 跳，**https 降到 http 直接拒**；
- **有体积上限**（512 MiB），超了中止，**不留下半个文件**；
- **签名默认从「包实际落在哪儿」取**（最终地址 + `.sig`），不是从你给的地址取——
  有重定向时后者会指向 404；`--sig-url` 可以显式指定；
- **下载来的包强制验签**：`model download` **不接受** `--allow-unsigned`。
  想强装请显式走 `model install <本地包> --allow-unsigned`；
- **下载失败与安装失败分开报**（`下载失败:` / `安装失败:`）——下一步动作不一样；
- 零新增依赖，用 JDK 自带的 HTTP 客户端，**核心包体积不变**。

> ⚠️ **发布方目前没有公开托管地址**：命令能跑，但要有一个真的 URL 才有意义。
> 详见 `docs/M4-阶段状态.md` §十四。

### 模型包的签名与信任

模型包是**独立分发**的产物，来源可能不可信。
一个「自洽的坏包」（清单合法、摘要合法、模型能加载，但**故意漏识别人名**）
能通过上面所有的校验——装上去之后工具照常跑、照常说「脱敏完成」，
而人名就留在输出文件里了。旁挂的 `.sha256` 挡不住它：
摘要和包是一起分发的，一起换掉就过了。

所以模型包必须**由受信任的公钥签过名**才装得上（Ed25519，签 zip 的 SHA-256）：

```bash
LightMeter model trust add 发布方公钥.pem       # 信任一把公钥（写进 ~/.litemask/trust/anchors.json）
LightMeter model trust list                      # 列出已信任的公钥
LightMeter model trust remove <密钥标识>          # 不再信任一把公钥
LightMeter model install 模型包.zip               # 没签名 / 钥匙不认 / 签完被改 → 装不上
LightMeter model install 模型包.zip --allow-unsigned   # 强装（会明确提醒「没有验签」）
```

几点要知道的：

- **密钥标识由公钥派生**（`ed25519-` + 公钥摘要前 6 位），不用手写——
  手写的标识一定会打错，而「标识对不上」在验签时表现为「不被信任」，用户看不出是自己打错了；
- **拒绝理由会逐条说清卡在哪一环**：没有签名文件 / 签名文件坏了 / 算法不是 Ed25519 /
  签的是另一个包 / 这把钥匙不认 / 验签不过——每一种的下一步动作都不一样；
- **验签在动磁盘之前**：装不上时这台机器上不会多出任何东西，原来那份也没被动；
- 程序**内置**一份信任锚（`model-trust-anchors.json`），目前**是空的**——
  谁持有发布私钥是发布方的运营决策。在它被填上之前，
  开箱即用装不了模型包（这是 fail-closed 的正确表现，不是故障）；
- 发布侧的工具在 `tools/model-signer.sh`（`keygen` / `pubkey` / `sign` / `verify`），
  **不随程序分发**——发行包里不该躺着一个能处理私钥的程序。

### 多个模型包版本

模型包是独立迭代的产物，**新版本不一定比旧版本好**。
而没有模型包时中文人名与机构名**不会被脱敏**——那是一份没脱干净的文档，
所以「装新版本」必须可逆。

```bash
LightMeter model list
# 模型包位置: /Users/你/.litemask/models/ner
# * 当前生效: litemask-ner-zh-char-v4-3f2a1b0c9d8e（模型 id: litemask-ner-zh-char-v4）
#     目录: /Users/你/.litemask/models/ner
#   保留的历史版本: litemask-ner-zh-char-v3-88c0d1e2f3a4（模型 id: litemask-ner-zh-char-v3）
#     目录: /Users/你/.litemask/models/ner.versions/litemask-ner-zh-char-v3-88c0d1e2f3a4

LightMeter model rollback          # 退回最近换下来的那一版
LightMeter model rollback 88c0d1e2f3a4   # 退回指定版本（可以只写摘要那一段）
LightMeter model remove 88c0d1e2f3a4     # 删掉一个历史版本（腾磁盘）
```

几点要知道的：

- 版本键是**内容寻址**的（`id` + 目录内容摘要前 12 位），
  所以同一个包重复装不会多出历史条目；
- `model remove` 删掉**当前生效**的那一份 = **卸载模型包**：
  工具会明说「人名与机构名不会被脱敏」；
- 历史最多留 **8 个版本**，超了会删最旧的（并告诉你删了哪个）；
- 用 `--to` 装到别处的模型包，它的历史也放在那个目录旁边，
  所以 `list` / `rollback` / `remove` 也要带同一个 `--to`；
- 装模型包时会加锁：两个人同时装，**后一个会明确失败**并告诉你有人在装，
  不会把先装好的那份弄坏。

如果只有模型目录、没有 zip，也可以直接放进上面查找顺序里的任意一个目录：
把 `manifest.json` / `ner.onnx` / `vocab.txt` 三个文件放进去即可，
**不要复制目录里的其它文件**（例如开发期残留的 `.bak`）。

### 卸载：磁盘上还剩什么

卸载一个脱敏工具，真正要紧的不是「程序文件删了没」，
而是**磁盘上还剩什么**。本工具会留下三样东西：

| 留下什么 | 在哪 | 性质 |
|---|---|---|
| 模型包（当前 + 历史版本） | `~/.litemask/models/ner` | 应用数据，重新装一次就有 |
| 信任锚（你加过的公钥） | `~/.litemask/trust/anchors.json` | 应用数据，重新加一次就有 |
| 任务工作区（脱敏产物 + **映射文件**） | 默认 `$TMPDIR/litemask-workspace` | **用户数据** |

映射文件里是**可还原的原始信息**——它留在磁盘上，
就等于「脱敏了但原始内容还在」。所以：

```bash
LightMeter uninstall                    # 只清应用数据（模型包 + 信任锚）
LightMeter uninstall --all              # 连用户数据一起清（含映射文件）
LightMeter uninstall --all --dry-run    # 只看会删什么，不真删
LightMeter uninstall --all --workspace /你/指定/的工作区
```

几点要知道的：

- **默认不删工作区**：里面可能有你还没取走的脱敏产物。
  想一并清就加 `--all`；跳过时它会**明说「保留（用户数据，要清请加 --all）」**，
  不会默默留着让你以为磁盘干净了；
- **只删本工具自己的东西**：你主目录下的合同、照片一个字都不动；
- **删不干净会报出来**（退出码非 0），不会假装成功；
- **不删程序本身**：`/Applications/LightMeter.app` 要你自己删
  （用 `.dmg` 装的就是拖到废纸篓），或者用系统 / `.pkg` 的标准卸载流程；
- 服务端如果用 `--workspace` 指了自定义目录，卸载时**要带上这个参数**，
  否则那个目录会留着。

## 五、已知限制

- ~~**PDF 无位置信息**~~ → **已于 2026-10-20 做掉**：
  命中会带上「第 N 页 · 文本块 M」，命中清单的「出现处」这一列会显示位置。
  **仍然缺的**：位置只到「页 + 文本块」，没有 x/y 坐标；
  「文本块」不等同于肉眼看到的行。
- **开机自启已经做了双平台**（macOS 用 LaunchAgent，Windows 用注册表 `Run` 键）：
  **两个平台的 `autostart status` 现在都会真的去探服务**
  （macOS 侧见 `docs/M4-阶段状态.md` §二十七，Windows 侧见 §二十八）：
  它分两句回答「装没装」与「服务在不在对外服务」，
  不可用时给出**原因**（连不上 / 连上了但没响应）、给出可核对的下一步，
  **退出码非 0**（以前一律报「已装载」并返回 0，等于把故障说成成功）。
  端口从**已写进去的那份配置**读（macOS 从 plist、Windows 从 `Run` 键里那条命令行），
  **读不到就明说「不知道」**，不猜一个默认端口去探。
  **仍然缺的**：① **探活不能区分「是不是本工具的服务」**（端口上若被别人占了别的服务、
  且它也返回 200，status 会说「在线」）；
  ② **探活有 1.5 秒超时**，「在但很慢」的服务会被报成「超时不可用」；
  ③ **真 Windows 上没验过**（注册表写入、引号转义、`Run` 键的登录触发都没在真机跑过）；
  ④ Windows 侧用 `Run` 键**没有自愈**（服务崩了不会自己回来）——
  所以 Windows 侧 `status` 在不可用时会**明说这一点**，并给出手工启动命令；
  ⑤ Windows 侧**不杀已运行进程**，卸载只删注册表值；
  ⑥ 「重启机器后它自动起来」这条只在当前登录会话里验过（真装真起真杀），
  **没有在真机重启后验证过**；
  ⑦ Windows 的注册表**值名是全局的**：`HKCU\...\Run` 下同名值会被覆盖
  （默认名与 macOS 一致 → 换用户时可能要手工挑个名）。
- **「只保留第 N 处」（位置级排除）已经能用**：命中清单的「出现处」每一处前面
  有一个小勾选框，勾上它就只保留那一次出现，同一个值的其它出现处照常脱敏。
  界面按**出现序号**铺行（默认只显示前 3 条，可点「展开全部」看全部），
  **第 4 次及以后的出现也选得到**（见 `docs/M4-阶段状态.md` §二十六）。
  **仍然缺的**：① 位置**没有 x/y 坐标**（只有「第 N 页 · 文本块 M」这类说明）；
  ② **位置说明**有上限：服务端每个值最多下发 20 条位置说明，
  第 21 次以后**没有位置说明**（界面上显示为「第 N 次出现（没有位置说明）」），
  但**照样能勾**（位置说明是给人看的，序号才是机器认的）；
  ③ 「原文里紧挨着」拼成一个标识符的那几行**不给**单处勾选框——
  只放开其中一段会留下**半截标识符**，服务端对这种请求也直接拒绝。
- **扫描件 PDF 没有文本层**：会明确报出「这份 PDF 没有文本层」，
  而不是报「文档干净」——前者是没脱到，后者才是真的没有。
  **而且不再产出「脱敏件」**：那种 PDF 脱敏跑完是零命中，出来的文件与**原件逐字相同**
  （图片里原封不动），当成脱敏件交出去就是在掩盖未处理的内容。
  命令行会**报错并删掉产物**（退出码非 0），本机服务那边同样拒掉；
  请先把它转存为带文本层的 PDF 再来脱敏。
- ~~**跨段落被切断的标识符会被按段内形状重新归类**~~ → **已于 2026-10-20 做掉**
  （docx / xlsx / pptx，见 `docs/M4-阶段状态.md` §十五）：
  身份证这类标识符被段落或单元格切开时，工具会认出「上一段的尾巴 + 下一段的头」
  拼起来是一个完整标识符（并过校验位），然后**按该类型**给每一段碎片脱敏；
  文本一个字节不动，所以**还原仍然逐字一致**。
- ~~**PDF 里被文本块切断的标识符整张留在交付物里**~~ → **已于 2026-10-20 做掉**
  （见 `docs/M4-阶段状态.md` §十七）：
  PDF 的续接**只在同一个内容流内**、且**只允许有真校验位的规则**参与
  （身份证 / 统一社会信用代码 / 银行卡）——
  **被文本块切断的身份证现在会被脱敏**，令牌类型是身份证（不再是手机号），
  还原仍逐字一致。
  **仍然缺的**：① **手机号、邮箱不参与**（它们没有校验位，放开就可能把多栏版式上
  两栏的数字拼成假手机号）——被文本块切断的手机号**仍会漏**；
  ② **跨页、跨表单不续接**（那两个块之间没有任何「本来就连着」的依据）。
- ~~**OOXML 侧未按 zip 部件分组**~~ → **已于 2026-10-20 做掉**
  （见 `docs/M4-阶段状态.md` §十八）：
  跨单元续接**只在同一个 zip 部件内**成立——docx 的 `document.xml` 与 `header1.xml`、
  xlsx 的 `sheet1.xml` 与 `sharedStrings.xml`、pptx 的 `slideN.xml` 与 `chartN.xml`
  里的单元**不再被拼在一起**。
  改之前，页眉末尾的 16 位数字与正文开头的字母会拼成一个**形态合法的车架号**，
  于是两段都被按「车架号」脱敏——**误判 + 标签错**（原文里根本没有车架号）。
  **仍然缺的**：**同一部件内部**的独立容器之间仍会续接
  （docx 的文本框段落与正文段落同在 `word/document.xml`）。
- ~~**OFD 里被 TextObject 切断的标识符整张留在交付物里**~~ → **已于 2026-10-21 做掉**
  （见 `docs/M4-阶段状态.md` §二十）：
  OFD 的续接**只在同一个 zip 部件内**、且**只在几何连续的 TextObject 之间**成立
  （同一行、纵向重叠容差 0.2 毫米、水平间隙 ≤ 1.0 毫米），
  **只允许有真校验位的规则**参与（身份证 / 统一社会信用代码 / 银行卡）——
  **被切成相邻两个 TextObject 的身份证现在会被脱敏**，
  两段碎片**各拿各的令牌**（`<身份证1>` / `<身份证2>`，不合并），
  文本一个字节不动，**还原仍逐字一致**。
  **仍然缺的**：① **两栏版式不续接**——两栏各 6 位凑不出完整身份证，
  前半段会**按原样留在交付物里**（刻意 fail-open：宁可漏脱不错配），
  后半段仍**可能被手机号规则误标**；
  ② **拿不到 Boundary 的对象一律不许续接**（对象**内部**照常脱敏，只是不跨对象拼）；
  ③ **没有校验位的规则不参与**（手机号、邮箱——与 PDF 侧同理）；
  ④ **跨页、跨部件不续接**。
- **值只剩一半、后半段根本不在文档里时判不出来，不脱**（宁可漏也不乱脱）；
  一个值被切成两段会拿到**两个令牌**（「不合并」的必然结果，换来还原仍逐字一致）。
- **装了模型包时，一个邮箱偶尔会被拆成两个令牌**（`<人名1>` + `<邮箱1>`）：
  NER 把邮箱的前半段认成了人名（人名命中的优先级高于邮箱规则），
  剩下的尾巴再按邮箱规则脱敏 → 同一个邮箱占掉两个令牌位。
  **不泄漏**：两段都脱敏了，还原仍逐字一致；
  后果是**令牌的类型与编号可能和你预期的不一样**。
  这条**块 13 之前就有**，与跨单元续接无关。
- ~~**长任务有进度反馈与取消，但没有超时**~~ → **已于 2026-10-20 做掉**：
  界面报「已处理 N 个文本单元」并能取消；跑太久会自动停，终态 `timed_out`
  与「用户自己取消」**分开说**，超时后**不产出任何文件**。
  时限默认 30 分钟，可用 `serve --task-timeout` 调，0 表示不设时限。
  **仍然缺的**：超时是**协作式**的——要等管线跑到下一个检查点才停；
  管线卡在某个不检查取消的地方时，只能把任务标成超时、停不下来。
- **崩溃残留会自动清理，但断电这一形态不保证**：进程被强杀（SIGKILL）后，
  原文档会在下一次启动时被清掉（靠会话持有的文件锁判定生死）；
  但**掉电**时锁文件可能没落盘，那一次会话可能留在盘上。
  见 `docs/M2-c-阶段状态.md` §5.10。
- ~~**模型包没有独立安装包**~~ → **已于 2026-10-20 做掉**：
  现在有 `LightMeter model install <模型包.zip>`，走确定性 zip + 旁挂摘要，
  校验通过才换装、装失败不毁掉原来那份（见 §二）。
  ~~**模型包签名没做**~~ → **已于 2026-10-20 做掉**：
  Ed25519 分离式签名 + 信任锚，模型包必须由受信任的钥匙签过名才装得上（见 §二）。
  **仍然缺的**：~~模型包**本身**的分发渠道（官网/对象存储下载页）没做，
  目前只能把 zip 递给用户~~ → **已于 2026-10-20 做掉工具侧**：
  现在有 `LightMeter model download <地址>`，取包 → 验签 → 装上一步做完（见 §二）。
  **仍然缺的**：**发布方尚无真实托管地址**（运营侧未决）、
  界面里没有「下载模型包」的入口；
  **发布私钥由谁保管还没定**——
  内置信任锚因此是空的，在它被填上之前开箱即用装不了模型包。
- ~~**换装成功即删旧版，没有一键回退**~~ → **已于 2026-10-20 做掉**：
  旧版本进 `~/.litemask/models/ner.versions/`，
  `LightMeter model list` 看得到、`LightMeter model rollback` 退得回去（见 §二）。
  **仍然缺的**：历史只留 8 个版本（超了删最旧的），且没有「按版本混用」。
- **Windows 上装模型包建议先关掉工具**：换装要把旧目录挪开，
  而 Windows 不允许移动正被打开的文件（模型文件被推理引擎打开着）。
  macOS 上没这个问题。这条**未在 Windows 上实测**。
- **Windows 版尚未产出**：`jlink` 不能在 macOS 上交叉构建 Windows 运行时。
- **核心包体积闸门已经扩到 Windows 侧（但没在真机跑过）**：
  判定逻辑搬进了**纯 JDK**（`com.litemask.pack.SizeGate`），
  `tools/package-windows.ps1` 会在**打安装包之前**调它，
  不过就**非 0 退出**（不会出现「验证没过但照样 PASS」）。
  预算（90 MiB）与三层口径的唯一真源是 `tools/size-budget.properties`，两端读同一份。
  必需层缺失 → 判失败（fail-closed）；可选层缺失 → 显式标出来。
  **仍然缺的**：**Windows 侧的真实体积没量过**（win-x64 的 jlink 运行时与 `.dll`），
  而**那段 PowerShell 从未执行过**（本机不能交叉构建 Windows 运行时）
  → 本轮只过了**静态契约**检查（接线形状对不对），运行时行为未验。
- **平台原生库完整性已经进打包闸门**：每个平台的包只带自己那套推理原生库，
  打包时当场核对，缺了或混进别的平台的**直接打包失败**
  （策略表与校验器见 `docs/M4-阶段状态.md` §二十三）。
  **仍然缺的**：**Windows 打包脚本从未执行过**（本机不能交叉构建 Windows 运行时），
  所以「Windows 包会守住 win-x64」目前只有逻辑与夹具验证，**没有真机产出**。
- **映射件里存着原值，这一块已经能加密封装了**：
  命令行加 `--map-pass-env` / `--map-pass-file` / `--map-pass-stdin` / `--map-pass-prompt`
  （四选一），映射件就写成加密封装件（`litemask-sealed-map` v1），
  文件里**没有原值**，还原必须给同一个口令（用法见上文「映射件加密（可选）」）。
  **不给口令时**行为与从前完全一样，但映射件权限已收紧到 `600`。
  ~~**图形界面没有口令入口**~~ → **已于 2026-10-21 做掉**：界面复核卡片里有
  口令输入框，填了口令，下载出来的映射件就是加密封装件（详见 §二十五）。
  **仍然缺的**：① **口令没有找回**，忘了这份映射件就废了；
  ② 没做口令强度检查（空口令会报错，但 `123456` 照样收）；
  ③ **口令在 HTTP 请求体里是 `String`，不可变、擦不掉**，进程内存里那一瞬间
  仍有口令明文。
